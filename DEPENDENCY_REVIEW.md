# Dependency review

Reviewed 2026-07-25 for v1.0.1 using `npm audit`.

## Result

`npm audit --omit=dev` reports **3 high severity advisories**, all the same root cause: `sharp`, pulled in transitively by `next` for image optimization.

Down from 6 at the start of this review. Three were resolved by upgrading `next` from 16.2.11 to 16.2.12, a patch bump validated against the full test suite and production build.

## Remaining: sharp via next

`sharp <0.35.0` inherits four libvips advisories (CVE-2026-33327, CVE-2026-33328, CVE-2026-35590, CVE-2026-35591).

**Not fixable from this repository.** `sharp` is a transitive dependency of `next`, pinned by Next's own dependency range. `npm audit fix --force` proposes downgrading to `next@9.3.3`, which is a five-major-version regression and would destroy the application. That is npm's resolver being unhelpful, not a real remediation.

**Exposure assessment.** These are image decoding vulnerabilities in libvips, reachable only by processing an attacker-supplied image. Ground Control accepts no image upload from any user. The only images in the application are the demo screenshots in `public/screenshots`, which are generated by our own Playwright run from our own pages. On Vercel, image optimization runs on Vercel's platform rather than the bundled `sharp` binary in the deployment.

**Conclusion:** present in the tree, not reachable by an attacker through any code path this application exposes. Tracked for the next Next.js release that bumps `sharp`.

## A note on `shadcn`

`shadcn` is listed in `dependencies` rather than `devDependencies`, which looks wrong for a CLI tool, and it drags in `@modelcontextprotocol/sdk` and `@hono/node-server` with a moderate path traversal advisory.

It was removed during this review and the build immediately failed: `src/app/globals.css` imports `shadcn/tailwind.css`, so the package supplies a stylesheet consumed at build time. It was restored.

The advisory is in the Hono server adapter, which is server code inside a CLI that is never imported, never started, and never deployed. Nothing in the application's runtime graph reaches it. Moving the package to `devDependencies` would be tidier and is worth doing when the CSS import can be replaced, but it does not change the exposure.

## Policy

- No major version upgrades in a hardening release without validating the whole application.
- Patch and minor upgrades that resolve an advisory are applied and validated.
- An advisory that cannot be fixed is documented with an honest exposure assessment rather than suppressed or ignored.
- `npm audit fix --force` is never run. It has proposed a five-major-version downgrade once already.

## Re-running

```bash
npm audit --omit=dev
```

`--omit=dev` is the number that matters. Development-only advisories affect the build machine, not the deployed application, and conflating them makes the real figure meaningless.
